# TimeFilter 训练 StockMixer 数据集使用说明

当前 SP500 配置用过去 **16 个交易日、每股 5 维行情**预测下一交易日各股收益率。`forecast.input_features: returns` 可切回原来的单收益率输入；NASDAQ、NYSE 目前仅支持该模式。金融输入适配和严格图掩码均可配置，TimeFilter 主干仍保留。

## 1. 如何运行

PowerShell 中执行，使用解释器 `C:\Users\marti\anaconda3\envs\timefilter\python.exe`：

```powershell
cd D:\finance\model\Timefilter\TimeFilter
conda activate timefilter

# 先训练一轮检查流程，再按 config.yaml 正式训练
python scripts/run_financial.py --dataset SP500 --epochs 1
python scripts/run_financial.py --dataset SP500

# 调参阶段只保存验证集最佳权重，不做最终测试；方案确定后再用 best.pth 独立测试
python scripts/run_financial.py --dataset SP500 --financial_validation_only

# 切换市场前，先在 config.yaml 将 input_features 改为 returns，选模改为 RankIC 或 mse
python scripts/run_financial.py --dataset NASDAQ --epochs 100 --batch-size 4

# 仅测试已有权重：使用原训练的配置，并指定其 best.pth
python scripts/run_financial.py --dataset SP500 --mode evaluate --checkpoint "D:\完整路径\best.pth"
```

配置文件是本项目的 `config.yaml`，命令行参数优先。旧入口 `python scripts/run_sp500.py` 仍可用。独立测试会校验 `best.pth` 所属实验的 `config.yaml`；新实验还会检查代码和数据指纹。配置或数据不一致会报错；仅代码变化会提示并继续评估，结果使用当前代码。若当前配置已改变，请先按原实验的参数设置配置文件。旧实验没有指纹，只能校验配置。

| 常用配置 | 含义 / 当前值 |
| --- | --- |
| `dataset` / `data_root` | 市场名称 / 数据父目录 `stockmixer_dataset` |
| `forecast.seq_len` / `pred_len` | 历史长度 16 / 预测长度固定为 1 |
| `forecast.input_features` | `eod5`：SP500 五维行情；`returns`：原单收益率输入 |
| `model.patch_len` | 片段长度，当前 8；必须整除 `seq_len` |
| `model.d_model` / `d_ff` / `e_layers` | 模型宽度 512 / 前馈宽度 2048 / 层数 2 |
| `training.train_epochs` / `batch_size` | 当前 100 轮 / 每批 32 个历史窗口 |
| `training.learning_rate` | 初始学习率 0.0001，使用 cosine 调度 |
| `training.optimizer` / `weight_decay` | 当前金融候选为 AdamW / 0.0001；改回 `adam` 时需将 weight decay 设为 0 |
| `training.grad_clip_norm` | 当前为 1.0，限制全局梯度范数；设为 0 关闭，逐轮记录裁剪比例 |
| `training.rank_weight` | 当前待验证候选为 5；2026-10-05 已完成实验为 0.1 |
| `training.moe_aux_weight` | MoE 辅助损失权重，当前 0.005；0 关闭辅助项 |
| `training.financial_seed` | 随机种子，当前 2021 |
| `training.financial_selection` | 当前 `stockmixer_val_loss`：验证集 MSE＋0.1×横截面排序损失，越低越好；也可选 `RankIC`、`mse`、`IC` |
| `training.test_each_epoch` | 当前 `true`：每轮后评估 Test；设为 `false`：只在训练结束加载 `best.pth` 后测试 |
| `training.stockmixer_selection_rank_weight` | 选模排序权重，当前 0.1；独立于训练用的 `rank_weight` |
| `runtime.cpu` / `gpu` | 默认使用 GPU 0；`cpu: true` 改用 CPU |

金融训练完成指定轮数，不提前停止。`training.test_each_epoch: true` 时，与 StockMixer 官方训练循环一样，每轮结束后评估并记录 Validation、Test 指标；设为 `false` 时只逐轮评估 Validation，最终仍会测试。**只用 Validation 选模**，每轮保存 `last.pth`，验证指标改善时更新 `best.pth`；训练结束后加载 **best** 生成最终测试预测与报告。`--financial_validation_only` 则跳过全部 Test。逐轮 Test 用于观察，不参与选模；权重不含恢复训练所需的优化器状态。

训练时终端每轮显示批次进度、该轮已用与预计剩余时间、累计已用时间及预计总剩余时间；预计值会随训练速度调整。`terminal.log` 每轮只保留一行进度汇总。

已有 timefilter 环境无需重装 PyTorch；若缺少 YAML 依赖，执行 `python -m pip install -r requirements-financial.txt`。显存不足时减小 batch size。

## 2. 数据集结构与划分

```text
stockmixer_dataset/
├── SP500/
│   └── SP500.npy
├── NASDAQ/
│   ├── price_data.pkl
│   ├── gt_data.pkl
│   └── mask_data.pkl
└── NYSE/
    └── 同 NASDAQ 的三个文件
```

- **SP500**：原数组为 `[474只股票, 2526天, 5项特征]`，特征依次为开盘、最高、最低、成交量、收盘。`eod5` 直接读取前 16 天的五维数值；`returns` 只读取由收盘价算出的历史收益率。两种模式的标签均为 `当日收盘 / 前日收盘 - 1`；0.01 表示上涨 1%。
- **NASDAQ / NYSE**：三个数组均为 `[股票, 天]`，分别保存价格、日收益率、有效掩码。原目录中的多特征文件 `eod_data.pkl` 当前不读取。
- SP500 的 `baseline_data_sp500.npy`、`sp500_ticker.csv` 当前也不参与训练。

| 市场 | 股票数 | 窗口为 16 时：训练 / 验证 / 测试样本数 |
| --- | ---: | --- |
| SP500 | 474 | 990 / 253 / 352 |
| NASDAQ | 1026 | 本地版本为 739 / 252 / 237 |
| NYSE | 1737 | 取决于实际文件；当前本地文件为空，需先补齐 |

一个样本对应**一个预测日的全体股票**。SP500 从原数组下标 915 开始，按 1006/253/352 天划分；训练段留出 16 天历史后剩 990 个样本。NASDAQ/NYSE 在下标 756、1008 处分界，首日无法计算收益率，训练从目标日下标 17 开始。

按**目标日期**划分数据，训练标签不会跨入验证集；验证和测试可使用此前已观测的历史。NASDAQ/NYSE 的缺失输入填 0，仅对历史窗口及目标收益率均有效的股票计算预测损失和金融指标。

SP500 的上述划分与 StockMixer **论文**表 1 一致：裁剪后目标日训练 `16..1005`、验证 `1006..1258`、测试 `1259..1610`；原始 `SP500.npy` 中对应测试日下标 `2174..2525`。两份本地 `SP500.npy` 已核对为同一 SHA-256 内容。注意：本地 StockMixer 历史运行 `20260705_165640_SP500` 保存的配置却是 `valid_index=756, test_index=1008`，测试 603 天，不能直接和当前 TimeFilter 的 352 天结果比较；StockMixer 默认配置中的这两个数也是 NASDAQ 示例，不是论文 SP500 划分。

## 3. TimeFilter 结构与 StockMixer 的对齐程度

```text
历史五维行情 [batch, 16, 股票数, 5]
  → 每股每个 patch 的 8×5 值投影到 d_model → 建图与关系筛选 → 图网络
  → 预测层 → 下一日收益率 [batch, 1, 股票数]
```

每只股票仍是一个通道（共 474 个），五维特征只进入 patch 投影层，不当成额外股票。`eod5` 沿用 StockMixer 发布的五维数值，要求 `model.norm=false`；原单收益率路径保持可选，核心图网络未改。

| 对比项 | 当前 TimeFilter | StockMixer 原始实现 |
| --- | --- | --- |
| 每只股票的输入 | 当前为 5 项行情特征；可切回单收益率 | 5 项行情特征 |
| 关系建模 | 股票与时间 patch 之间的图 | 指标、时间和股票维度的混合 |
| 训练目标 | `MSE + rank_weight × 排序损失 + moe_aux_weight × MoE辅助损失`（当前待验证为 5 / 0.005） | 收益率 `MSE + 0.1 × 排序损失` |
| 验证选模 | 当前用 `MSE + 0.1 × 排序损失`，不含 MoE；仅看验证集 | 同样按验证集总损失最小选权重 |
| 最终评价 | 下一日收益率的金融指标 | 下一日收益率的金融指标 |

五维输入、数据日期和选模口径已对齐本次 SP500 StockMixer 运行，但两模型的主干、训练损失、优化过程及 batch 不同，不能把成绩差距全归因于主干。`returns` 与 `eod5` 应分别从头训练，只改这一项来衡量输入信息的作用。

当 `seq_len=16、patch_len=16` 时，每只股票只有一个 patch，图中没有跨 patch 的时间/时空关系，16 日历史仍进入片段嵌入。patch=8 或 4 可得到 2 或 4 个片段，但显存需求明显增加。`model.alpha` 是建图参数，**不是** `training.moe_aux_weight`。

## 4. 评价指标怎么看

优先查看 `test_metrics.json`。金融指标按每日股票截面计算后汇总；缺失数据按当前实现的掩码规则处理。

| 指标 | 简单含义 | 好坏方向 |
| --- | --- | --- |
| **IC** | 每天预测收益与真实收益的 Pearson 相关，再取均值 | **越高越好**；近 0 表示线性关联弱，负值表示反向关联 |
| **RIC** | 日 IC 的均值 ÷ 标准差，即本实现的 **ICIR** | **越高越好**；反映相关性的方向和稳定性 |
| **RankIC** | 每天预测排名与真实排名的 Spearman 相关均值 | **越高越好**；更关注股票排序 |
| **RankICIR** | 日 RankIC 的均值 ÷ 标准差 | **越高越好** |
| **Precision@10**（`prec_10`） | 预测最高的 10 只有效股票中，实际收益 ≥ 0 的比例，再按日平均 | **越高越好**；0.55 即 55%，不是命中真实前十名的比例 |
| **SR(top5)**（`sharpe5`） | 预测最高的 5 股等权组合：日收益均值 ÷ 标准差 × 15.87 | **越高越好**；未扣交易成本或无风险收益 |
| **MSE / RMSE / MAE** | 预测收益率与真实值的数值误差 | **越低越好**；误差小不等于选股排名好 |
| **directional_accuracy** | 预测与真实收益符号相同的比例 | **越高越好**；应结合样本涨跌比例判断 |

**RIC 不等于 RankIC。** 此处 `RIC` 严格沿用 StockMixer 开源 `src/evaluator.py` 的计算：每日 Pearson IC 的均值除以标准差，即 ICIR。论文文字却把 RIC 定义为平均 Spearman；本项目对应的字段是 `RankIC`。论文表 2 的 RIC 数值实际采用哪种口径不能仅凭论文文字和公开代码确定，勿与本项目 `RIC` 直接横比。IC、RankIC 的范围为 [-1, 1]；RIC、RankICIR、SR 没有这个范围限制。无法计算的指标在 JSON 中记为 `null`，不是 0。不同市场、测试区间或评估规则的数值不宜直接比较。

Train Loss 含 MoE 辅助项，终端逐轮 `Vali Loss` / `Test Loss`（开关开启时）只含预测 MSE，不能直接横比。当前另算并记录 `val_stockmixer_val_loss`（逐日 MSE＋0.1×排序损失的日期均值），仅据此选 `best.pth`；验证阶段不加 MoE。金融 `Vali Loss` / `Test Loss` 按目标日加权汇总，最后不足一批的日期权重不变。

## 5. 结果保存与可选对比实验

每次新实验创建 `outputs/SP500_YYYY_MM_DD_HH_MM/`（其他市场替换前缀）。同一分钟创建的不同实验加 `_02`、`_03`，避免覆盖。

同配置、同代码、同数据的训练正在运行时，会阻止重复启动；已经完成时，提示已有结果目录，不再训练或新建目录。新实验的 `provenance.json` 保存实际读取的代码和数据文件 SHA-256。代码或数据内容变化会自动创建新实验；历史实验没有指纹，无法证明版本一致，首次重新运行不会复用。确需重复同一版本，使用 `python scripts/run_financial.py --force-rerun`。仅测试模式不做结果复用。

| 文件位置（实验目录内） | 内容 |
| --- | --- |
| `terminal.log` / `run_status.json` | 完整日志 / 完成或失败状态 |
| `config.yaml` / `source_config.yaml` | 实际参数 / 原始 YAML 副本 |
| `checkpoints/<setting>/best.pth`、`last.pth` | 最优、最后一轮权重 |
| `results/<setting>/financial/epoch_metrics.csv` | 各轮损失分项、金融指标等 |
| 同目录的 `selection.json`、`test_metrics.json` | 最佳轮次与依据 / 最终测试成绩 |
| 同目录的 `test_predictions.npz`、`data_split.json` | 预测数组 / 数据划分 |

预测文件中的 `prediction`、`ground_truth`、`mask` 均为 `[股票, 测试日]`；日期字段是数组下标，不是真实日期或股票代码。新预测文件还记录 `lookback_length` 与 `horizon`；旧文件由同目录 `config.json` 核对窗口长度。

### 先检查 MoE 辅助损失的影响

在已激活 timefilter 的项目目录中，依次运行三组（关闭 / 降为原来的十分之一 / 原权重）：

```powershell
python scripts/run_financial.py --dataset SP500 --moe-aux-weight 0
python scripts/run_financial.py --dataset SP500 --moe-aux-weight 0.005
python scripts/run_financial.py --dataset SP500 --moe-aux-weight 0.05
```

三次之间不要改 `config.yaml` 的其他项，均从头训练，保持当前五维输入、种子 2021、100 轮、batch=32、patch=8、学习率和验证集 StockMixer 总损失选模规则不变。也可以手动修改 YAML 的 `training.moe_aux_weight`，命令行参数优先。权重为 0 仅去掉辅助训练目标，仍保留 MoE 路由、辅助值计算和原模型结构。

每次输出目录中的 `config.yaml` 记录实际权重；`epoch_metrics.csv` 中查看 `train_mse`、`train_moe`（未加权）、`train_moe_weighted`、`val_stockmixer_val_loss`。**不要按总 Train Loss 大小判断哪组更好**，应按预先固定的验证集选模规则选择权重，再报告相应 best 权重的测试 IC、RIC、RankIC 等。单种子结果用于初筛，后续可固定候选权重，用相同的一组种子复验。

### 模块化金融适配实验

当前 `config.yaml` 的 `finance_adaptation.enabled` 是 `true`；设为 `false` 可关闭这些金融适配模块。开启后，可以分别控制输入端 LayerNorm、五特征混合、patch 内时间混合、共享 patch 位置编码、严格图掩码，以及额外的每日 Pearson IC 损失。输入适配器只用于 `input_features: eod5`；它只读取预测日前的窗口，不反归一化收益率输出。轻量化主干仍通过 `model.d_model`、`model.d_ff`、`model.e_layers` 修改，训练排序损失权重仍通过 `training.rank_weight` 修改。

当前 Rank 权重 5、严格图掩码开启及 AdamW/梯度裁剪是**待验证的组合候选**，不代表已经提升成绩。需要定位收益来源时，分别改回旧值单独训练，再按同一验证规则比较。`loss.ic_weight` 当前为 0；若开启，训练总损失增加 `ic_weight × (1 - 每日 Pearson IC)`，验证选模仍使用现有 `stockmixer_val_loss`。
